Execution Steps

1

Read input: Retrieve input_top_event, procedure, rat from state file iteration slice.

2

Get spec skeleton: Call spec_query.py --operation skeleton to fetch standardized phases from 3GPP spec for the procedure.

3

Empty check (expected for iter ≥ 2): If skeleton returns phases: [], invoke fallback: spec_query.py --operation generate_hypotheses. Treat outputs as top-level hypotheses.

4

Bind modules: For each phase/hypothesis, call code_search.py --operation bind_module to find UE source files implementing that phase.

5

Assemble & write: Build hybrid_tree.branches[] with each phase/hypothesis as a top-level branch. All branches start status="unevaluated", gate_a_result=null, children=[].

Table isolation (hard rule): Gate A ONLY queries UE_3gpp_signaling_log. Gate B ONLY queries UE_Trace_log. Policy enforced at log_query.py layer.

Phase 3.2: Gate A (Signaling Evaluation)

Query signaling log for mandatory_messages defined on the branch. Interpret result:

Query Result Branch Status Action
Messages clean, no errors pruned_normal Prune. Add to pruned_branches[]. Skip Gate B.
Messages + failure indicators failure_here Confirm failure. Proceed to expansion.
Messages absent absent Proceed to expansion. Gate B may find evidence.
Unclear / partial match open Add to open_items[]. Skip Gate B.
Iteration ≥ 2, code-only fallback (no signaling defined) not_applicable. Skip Gate A, go directly to expansion.

Phase 3.3: Dynamic Expansion & Gate B

For branches that survived Gate A (failure_here, absent, or N/A):

1

Expand failure modes: Call code_search.py --operation expand_failure_modes. Extract literal log keywords from code log macros.

2

Create children: For each failure mode, create a child node under the branch. Assign IDs: P1.1, P1.2, etc.

3

Gate B query: For each failure mode, query UE_Trace_log using its log keywords.

4

Interpret Gate B: Matched → base_event_confirmed. No match → rejected. Unclear → open.

Anti-laziness: Evaluate ALL failure modes in an expanded branch, even if one is confirmed. No early exit.

Early-Exit Condition

If ALL branches pruned at Gate A: All top-level phases evaluated normally, no failure found. Iteration halts with signal "all_phases_normal_failure_not_in_skeleton". Iteration controller recommends abort or accept_terminal.

Iteration Budget

Default budget: 5 iterations. Tracked in meta.iteration_budget. When approaching budget:

  • Iteration controller recommends accept_terminal when at/near limit
  • User may still override and dig deeper, but audit records both recommendation and override

The Three Python Tools

spec_query.py
Operations: • skeleton — Get phases • extract_ies — Get IE definitions • generate_hypotheses — Fallback • expand_sub_causes — Fallback • find_commanded_values — Phase 3.4 Input: procedure, rat, top_event Output: phases, IE names, hypotheses
code_search.py
Operations: • bind_module — Find files/functions • expand_failure_modes — Extract logs • expand_sub_causes — Fallback • find_implementation — Phase 3.4 Input: phase_name, file path Output: module bindings, log keywords
log_query.py
Operations: • phase3_gate_a — Signaling query • phase3_gate_b — Trace query • phase3_cross_ref — Commanded vs actual • phase1/phase2 — Scoping & timeline Input: table, keywords, time_window Output: matched events, timestamps, summaries Table isolation: enforced at tool entry (rejects mismatches)

Exit Code Semantics

Exit Code Meaning Skill Action
0 Success Continue normal flow
1 Bad arguments / missing input Halt, error message
2 Tool unavailable Halt, tool missing
3 Policy violation (e.g., table isolation) Halt, policy error
4 Empty result (no matches) Continue, interpret as empty

Keyword provenance: Every keyword (message name, IE name, log string, function name) used in any query must originate from a prior tool invocation in the same iteration. This is enforced by keyword_provenance_audit[] and checked at runtime by log_query.py.

Summary: Key Architectural Principles

  • Iteration-based: FTA runs as a loop of iterations, not one flat tree. Each iteration has its own tree, base events, and root cause.
  • User gates: Checkpoint B after each iteration is mandatory. User chooses dig_deeper, accept_terminal, or abort.
  • State file is truth: All data flows through one JSON file at /tmp/rca_state_*.json. No skill holds state in memory.
  • Tool-driven: Skills invoke Python tools under 3gpp-tools/, never query data directly.
  • Table isolation: Signaling log (Phase 3.2) vs. Trace log (Phase 3.3) are segregated by policy, enforced at tool layer.
  • No hallucination: Every keyword must trace back to tool output. Keyword provenance audit records all sources.
  • No fix generation: Pipeline produces root cause + evidence chain, never fixes or patches.
